# i18n & Lokalisasi — Dokter HP Web App

> **Rancangan multi-bahasa masa depan.**
> Bahasa utama: Bahasa Indonesia (`id`). Bahasa kedua yang diprioritaskan:
> Inggris (`en`). Status: Fase 1 — dokumen + kerangka file, 17 November 2026.
>
> Acuan: `PRODUCT.md` (11 layar) dan `docs/copy.md` (teks final Bahasa
> Indonesia). Dokumen ini tidak mengubah komponen apa pun — hanya
> rancangan dan kerangka file terjemahan.

---

## 1. Keputusan pendekatan

### 1.1 Opsi yang dibandingkan

| Aspek | A. react-i18next (i18next + react-i18next) | B. Solusi ringan tanpa library |
|---|---|---|
| Cara kerja | File JSON per bahasa, dimuat lewat `i18next` + hook `useTranslation()` | File JSON per bahasa, diimpor langsung + hook `useT()` buatan sendiri (~60 baris) |
| Interpolasi | Bawaan (`{{nama}}`), sudah teruji | Harus ditulis sendiri (pengganti string sederhana) |
| Jamak (plural) | Aturan jamak bawaan per lokal (penting untuk Inggris: 1 attempt / 2 attempts) | Harus ditulis sendiri per bahasa; mudah salah |
| Fallback | Bawaan: kunci yang belum diterjemahkan otomatis jatuh ke Bahasa Indonesia | Harus ditulis sendiri |
| Muat malas (lazy load) | Bawaan: file bahasa dimuat saat dipilih, tidak memberatkan muat awal | Harus ditulis sendiri dengan `import()` dinamis |
| Deteksi bahasa | Plugin bawaan (localStorage + bahasa browser) | Harus ditulis sendiri |
| TypeScript | Kunci bertipe: salah ketik nama kunci ketahuan saat build (bila deklarasi tipe dibuat dari `id.json`) | Bisa dibuat bertipe, tapi pemeriksaan fallback dan jamak tetap manual |
| Ukuran bundle | Tambahan sekitar 8–10 KB (gzip) untuk `i18next` + `react-i18next` | Hampir nol |
| Ketergantungan | Dua paket npm yang umum dipakai dan aktif dirawat | Nol |
| Risiko | Kecil; library matang, dipakai luas | Sedang; setiap kebutuhan baru (jamak, format tanggal, fallback) menambah kode buatan sendiri yang harus diuji |

### 1.2 Rekomendasi: react-i18next (opsi A)

**Pakai react-i18next.** Alasannya:

1. **Aturan jamak sudah benar.** Bahasa Indonesia tidak membedakan
   bentuk tunggal/jamak, tetapi Inggris membedakan ("1 attempt" /
   "2 attempts"). Kunci seperti `pinLock.wrongWithAttempts` dan
   `security.permissionCount` butuh bentuk jamak yang benar di
   Inggris — i18next menanganinya dengan aturan baku per lokal
   (`count` + akhiran `_one` / `_other`), tanpa kode khusus.
2. **Fallback otomatis.** Kunci yang belum diterjemahkan di bahasa
   baru otomatis tampil dalam Bahasa Indonesia, bukan kunci mentah
   atau layar kosong. Ini penting karena Bahasa Indonesia adalah
   bahasa utama dan selalu lengkap.
3. **Interpolasi dan pemformatan sudah teruji.** Placeholder
   `{{nama}}`, `{{skor}}`, `{{tanggal}}` bekerja sama di semua bahasa,
   termasuk saat urutan kata berubah (misalnya tanggal di depan
   kalimat dalam bahasa lain).
4. **Muat malas per bahasa.** File `en.json` hanya diunduh bila
   pengguna memilih Inggris, sehingga muat awal tetap ringan —
   sesuai prinsip aplikasi ini yang bekerja di koneksi lemot.
5. **Kunci bertipe di TypeScript.** Deklarasi tipe yang dibuat dari
   `id.json` membuat salah ketik nama kunci gagal saat build,
   bukan saat aplikasi berjalan.
6. **Biaya bundle kecil** (sekitar 8–10 KB gzip) dan tidak ada biaya
   layanan — library sumber terbuka, tanpa server, tanpa kunci API.

Opsi B (solusi ringan tanpa library) tetap dicatat sebagai cadangan
bila suatu saat anggaran bundle menjadi sangat ketat. Namun opsi B
menggeser beban ke kode buatan sendiri: setiap bahasa baru menambah
risiko salah jamak, salah fallback, dan salah interpolasi — persis
masalah yang sudah diselesaikan i18next. Untuk aplikasi dengan
341 kunci dan rencana lebih dari dua bahasa, opsi A lebih murah
dalam jangka panjang.

### 1.3 Yang tidak dipakai

- **Terjemahan mesin otomatis di sisi klien** (misalnya widget
  terjemahan browser): tidak dipakai. Terjemahan aplikasi ini
  ditulis dan ditinjau manusia per kunci, agar nada tetap
  profesional dan jujur — terjemahan mesin bisa mengubah arti
  peringatan penting (misalnya hapus akun).
- **Satu file JSON raksasa tanpa kelompok:** kunci dikelompokkan
  per layar/fungsi (lihat bagian 3), agar tim bisa bekerja per layar
  tanpa konflik.

## 2. Struktur file

```
apps/web/src/i18n/
  id.json        # Bahasa Indonesia — bahasa utama, sumber kebenaran
  en.json        # Inggris — terjemahan lengkap kunci yang sama
  index.ts       # (rencana implementasi) konfigurasi i18next:
                 # bahasa bawaan id, fallback id, muat malas en
  types.d.ts     # (rencana implementasi) tipe kunci dari id.json
```

Aturan struktur:

- **Satu file JSON per bahasa**, nama file = kode bahasa ISO 639-1
  (`id`, `en`). Bahasa baru = file baru, tanpa mengubah kode.
- **`id.json` adalah sumber kebenaran.** Kunci baru ditulis dulu di
  `id.json`, lalu diterjemahkan ke bahasa lain. Kunci yang ada di
  `id.json` tetapi belum ada di bahasa lain jatuh ke Bahasa Indonesia
  (fallback), bukan tampil sebagai kunci mentah.
- **Kunci bersarang per kelompok**, memakai camelCase:
  `dashboard.scoreValue`, `wifi.sustainedRunning`,
  `errors.noInternet`. Kelompok = layar atau fungsi bersama
  (`common`, `nav`, `errors`, `success`).
- **Nilai adalah string final**, bukan potongan kalimat. Jangan
  menggabung potongan string di kode (`"Skor " + skor`) — susunan
  kata berbeda antar bahasa. Selalu pakai satu kunci utuh dengan
  placeholder.
- **Placeholder memakai gaya i18next `{{nama}}`** dan namanya
  deskriptif (`{{score}}`, `{{date}}`, `{{time}}`, `{{count}}`,
  `{{remaining}}`, `{{seconds}}`, `{{speed}}`, `{{classification}}`,
  `{{latency}}`, `{{start}}`, `{{end}}`, `{{name}}`, `{{device}}`,
  `{{appName}}`, `{{components}}`). Placeholder yang sama persis
  wajib ada di semua bahasa untuk kunci yang sama — diperiksa
  otomatis (lihat bagian 7).
- **Kunci yang sama di dua kelompok** (misalnya teks "PIN salah.
  Coba lagi." muncul di `pinLock.wrong` dan `errors.pinWrong`)
  sengaja diduplikasi per konteks di kerangka ini, agar tiap layar
  bisa mengubah nadanya sendiri tanpa memengaruhi layar lain.
  Saat implementasi, tim boleh menggabungkan duplikat yang benar-benar
  identik ke kelompok `common`/`errors` — tetapi penggabungan harus
  dilakukan di semua file bahasa sekaligus, agar kunci tetap sejajar.

### 2.1 Konfigurasi yang direncanakan (implementasi mendatang)

- Bahasa bawaan dan fallback: `id`.
- Deteksi awal: pilihan tersimpan pengguna (localStorage) didahulukan;
  bila belum ada, pakai bahasa browser bila didukung; bila tidak,
  pakai `id`.
- Pilihan bahasa disimpan per perangkat (localStorage), bukan di
  server — pilihan bahasa adalah preferensi perangkat, bukan data akun.
- Bahasa hanya memengaruhi teks antarmuka dan format tanggal/angka.
  **Data pengguna tidak diterjemahkan**: nama tampilan, nama aplikasi
  di Dokter Keamanan, dan jawaban AI tampil apa adanya.
- Laporan PDF memakai bahasa aktif saat laporan dibuat.
- Teks yang dibagikan lewat "Bagikan hasil" memakai bahasa aktif.

## 4. Format tanggal, waktu, dan angka lokal Indonesia (id-ID)

Semua pemformatan memakai `Intl` bawaan browser — tidak ada library
format tanggal/angka tambahan. Lokal aktif mengikuti bahasa aktif
(`id` → `id-ID`, `en` → `en-US`).

### 4.1 Tanggal dan waktu

| Kebutuhan | id-ID (Bahasa Indonesia) | en-US (Inggris) | Kode |
|---|---|---|---|
| Tanggal + jam di entri riwayat | `17 November 2026, 22.15` | `November 17, 2026, 10:15 PM` | `Intl.DateTimeFormat(lokal, { day: "numeric", month: "long", year: "numeric", hour: "2-digit", minute: "2-digit", hour12: … })` |
| Tanggal saja | `17 November 2026` | `November 17, 2026` | `{ day: "numeric", month: "long", year: "numeric" }` |
| Jam saja | `22.15` | `10:15 PM` | `{ hour: "2-digit", minute: "2-digit", hour12: … }` |

Aturan:

- **Bahasa Indonesia memakai jam 24 jam** (`hour12: false`) dan
  pemisah jam-menit **titik** (`22.15`), sesuai `docs/copy.md`.
  `Intl.DateTimeFormat("id-ID", …)` menghasilkan pemisah titik secara
  bawaan — jangan menggantinya dengan titik dua.
- **Inggris memakai jam 12 jam** (`hour12: true`, `en-US`) dengan
  AM/PM.
- **Bulan ditulis lengkap** ("November", bukan "Nov" atau angka) di
  kedua bahasa, agar mudah dibaca semua orang.
- **Tanggal disimpan sebagai ISO 8601** di server dan hanya diformat
  saat tampil. Jangan pernah menyimpan string tanggal yang sudah
  diformat.
- **Zona waktu:** waktu tampil memakai zona waktu perangkat pengguna
  (bawaan `Intl`). Tidak ada konversi zona waktu manual.
- Placeholder `{{date}}` dan `{{time}}` di kunci terjemahan diisi
  dengan hasil format di atas — bukan dengan string tanggal mentah.

### 4.2 Angka

| Kebutuhan | id-ID | en-US | Kode |
|---|---|---|---|
| Pemisah ribuan | titik: `1.000` | koma: `1,000` | `Intl.NumberFormat(lokal)` |
| Pemisah desimal | koma: `1,5` | titik: `1.5` | `Intl.NumberFormat(lokal, { maximumFractionDigits: 1 })` |
| Persen (level baterai, RAM) | `85%` | `85%` | Angka + `%` (tanda persen sama di kedua bahasa) |
| Skor 0–100 | `87` (tanpa desimal) | `87` | `Intl.NumberFormat(lokal, { maximumFractionDigits: 0 })` |

Aturan:

- **Jangan memformat angka dengan string manual** (misalnya
  mengganti `.` dengan `,`). Selalu pakai `Intl.NumberFormat`
  dengan lokal aktif.
- **Satuan tidak diterjemahkan lewat pemformat angka**: "KB/detik",
  "MB/detik", "GB", "MB", dan "detik" adalah teks — bila perlu
  diterjemahkan (misalnya "detik" → "seconds"), sediakan kunci
  terjemahan sendiri, jangan mengarang dari `Intl`. Di kerangka ini
  satuan kecepatan tampil sebagai bagian dari nilai hasil ukur
  (`{{speed}}` sudah berisi satuan) atau sebagai teks di kunci
  (misalnya `wifi.sustainedRunning` memakai kata "detik" / "second").
- **Angka di dalam kalimat** (misalnya "4 izin berbahaya",
  "30 detik", "20 pertanyaan") mengikuti aturan angka lokal bila
  angkanya diformat lewat `Intl`; angka kecil (di bawah 1.000)
  tampil sama di kedua bahasa.
- **Angka yang dijanjikan di copy** (30 detik tes bertahan,
  20 pertanyaan per hari, 5 kali PIN salah, kunci 30 detik,
  4–8 digit PIN) adalah nilai produk yang sama di semua bahasa —
  jangan mengubah angkanya saat menerjemahkan.

## 5. Bahasa kedua yang diprioritaskan: Inggris

**Bahasa kedua adalah Inggris (`en-US`).** Alasannya:

1. **Bahasa internasional yang paling luas.** Pengguna yang tidak
   berbahasa Indonesia — termasuk pengguna di luar Indonesia dan
   pengguna yang memakai HP berbahasa Inggris — paling mungkin
   memahami Inggris dibanding bahasa lain mana pun.
2. **Bahasa bawaan perangkat dan browser.** Bila bahasa browser
   pengguna bukan Indonesia, kemungkinan terbesar berikutnya adalah
   Inggris. Deteksi bahasa otomatis paling berguna bila Inggris
   tersedia sebagai cadangan.
3. **Bahasa dokumentasi dan istilah teknis.** Istilah seperti
   "latency", "channel", dan "DNS" berasal dari Inggris; terjemahan
   Inggris menjadi rujukan saat menambah bahasa ketiga, karena
   penerjemah bahasa lain umumnya bekerja dari teks Inggris.
4. **Biaya paling rendah.** Terjemahan Inggris bisa ditinjau paling
   mudah, dan aturan jamak Inggris sudah didukung penuh oleh i18next
   maupun `Intl`.
5. **Tidak mengubah produk.** Bahasa Indonesia tetap bahasa utama
   dan bawaan; Inggris hanya pilihan tambahan di Pengaturan, bukan
   pengganti.

Bahasa ketiga dan seterusnya diputuskan kemudian berdasarkan
permintaan pengguna yang nyata, bukan ditambahkan spekulatif.
Kandidat yang wajar bila ada permintaan: Melayu (`ms`, dekat dengan
Bahasa Indonesia sehingga biaya terjemahan rendah) dan Jawa (`jv`,
bahasa daerah terbesar di Indonesia) — keduanya belum menjadi
komitmen.

## 6. Checklist menambah bahasa baru

Salin checklist ini saat menambah satu bahasa (misalnya `ms.json`):

### Persiapan

- [ ] Tentukan kode bahasa ISO 639-1 dan kode lokal `Intl`-nya
      (misalnya `ms` → `ms-MY`). Catat di dokumen ini.
- [ ] Salin `id.json` menjadi `<kode>.json` baru sebagai kerangka
      (salin struktur kunci, bukan dengan `cp` saat EPERM —
      ikuti aturan tulis file proyek: file TEMP + `mv` atomik).
- [ ] Daftarkan bahasa baru di konfigurasi i18next (impor malas)
      dan di pemilih bahasa di Pengaturan.

### Terjemahan

- [ ] Terjemahkan **seluruh 341 kunci** — tidak ada kunci yang
      dibiarkan dalam Bahasa Indonesia, kecuali yang memang tidak
      diterjemahkan (nama produk, lihat bagian 3).
- [ ] Jaga **placeholder `{{…}}` sama persis** di setiap kunci:
      nama dan jumlahnya harus cocok dengan `id.json`.
- [ ] Jaga **angka produk** tetap sama (30 detik, 20 pertanyaan,
      5 kali salah, 4–8 digit, 4 izin berbahaya).
- [ ] Terjemahkan **kata konfirmasi hapus akun** (`settings.
      deleteAccountConfirmWord`) ke satu kata yang mudah diketik
      di bahasa itu, dan sesuaikan `settings.
      deleteAccountConfirmLabel` serta `errors.deleteConfirmWrong`
      dengan kata yang sama.
- [ ] Periksa **bentuk jamak**: bila bahasa baru membedakan
      tunggal/jamak (seperti Inggris), sediakan bentuk `_one` dan
      `_other` untuk kunci yang memakai `{{count}}`
      (`pinLock.wrongWithAttempts`, `security.permissionCount`,
      `security.reviewEntry`). Bila bahasa tidak membedakan jamak
      (seperti Indonesia), satu bentuk cukup.
- [ ] Periksa **panjang teks**: terjemahan yang jauh lebih panjang
      dari Bahasa Indonesia bisa merusak tata letak di layar 360 px.
      Uji tombol dan judul yang panjang di lebar 360 px.
- [ ] Jaga **nada**: bahasa sehari-hari yang mudah dicerna semua
      orang, tanpa istilah teknis, tanpa klaim berlebihan — sama
      seperti aturan `docs/copy.md`. Pesan galat tetap tanpa rincian
      teknis.

### Format lokal

- [ ] Tentukan format tanggal/jam lokal (24 jam atau 12 jam,
      pemisah titik atau titik dua, urutan hari-bulan-tahun) dan
      uji dengan `Intl.DateTimeFormat` di browser.
- [ ] Tentukan pemisah ribuan/desimal lokal dan uji dengan
      `Intl.NumberFormat`.
- [ ] Tambahkan baris lokal baru ke tabel di bagian 4 dokumen ini.

### Verifikasi

- [ ] Validasi JSON (tidak ada koma tertinggal, tidak ada kunci
      duplikat).
- [ ] Jalankan pemeriksaan kunci: setiap kunci di `id.json` ada di
      file baru, dan tidak ada kunci tambahan yang tidak ada di
      `id.json` (lihat bagian 7).
- [ ] Jalankan pemeriksaan placeholder: setiap kunci memakai
      placeholder yang sama dengan `id.json`.
- [ ] Uji manual: ganti bahasa di Pengaturan, buka ke-11 layar,
      pastikan tidak ada kunci mentah (`dashboard.scoreValue`)
      yang tampil dan tidak ada teks yang terpotong di 360 px.
- [ ] Uji fallback: hapus sementara satu kunci dari file baru,
      pastikan tampil Bahasa Indonesia (bukan kunci mentah),
      lalu kembalikan.
- [ ] Uji laporan PDF dan teks "Bagikan hasil" dalam bahasa baru.
- [ ] Perbarui jumlah kunci dan daftar bahasa di dokumen ini.

## 7. Pemeriksaan otomatis yang direncanakan

Saat implementasi i18n berjalan, tambahkan skrip pemeriksaan
(yang dijalankan sebelum build atau di CI) yang memastikan:

1. **Kunci sejajar:** himpunan kunci di setiap file bahasa sama
   persis dengan himpunan kunci di `id.json`.
2. **Placeholder sejajar:** setiap kunci memakai himpunan placeholder
   yang sama di semua bahasa.
3. **JSON valid:** semua file bahasa bisa dibaca sebagai JSON.
4. **Tidak ada string kosong:** tidak ada nilai terjemahan yang
   kosong (string kosong menandakan terjemahan yang belum diisi).
5. **Tidak ada teks antarmuka yang ditulis langsung di komponen:**
   pemeriksaan statis (grep pola string harcoded di `pages/` dan
   `components/`) sebagai pengingat, bukan pemblokir mutlak —
   pengecualian yang sah (misalnya nilai `HAPUS` yang sudah
   dipindah ke kunci) dicatat di sini.
